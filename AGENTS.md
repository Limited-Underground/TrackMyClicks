# TrackMyClicks contributor entrypoint

Read README.md, CONTRIBUTING.md and docs/PROJECT_STATUS.md before work. These files are the portable human/AI pickup route. The dedicated organization Project owns live task status; its status does not authorize publication or release.

Keep work within the authorized task. Preserve unrelated dirty work, user profiles, prior builds and recovery evidence. Never commit databases, local evidence, credentials or machine-specific paths. Input identities may exist transiently for repeat suppression; never persist typed content or identities. No telemetry, application history, screenshots during normal tracking, or application network communication.

Use focused validation. Record exact source identity, worker/edit scope, results and limits, blockers and next action in the owning task and maintained status file. Use one primary agent unless delegation has a clear independent purpose. Do not create duplicate tracking systems. Do not imply that automated tests establish human acceptance.

No destructive cleanup, force push, history rewrite, unrelated changes or release publication without applicable authorization. Closeout includes temporary files removed; retained files and purpose; branch/worktree state; preserved evidence; cleanup requiring approval. Keep private evidence local.
