# Security reporting

TrackMyClicks is experimental; no supported public binary release is established. Product development is frozen. [Status](docs/PROJECT_STATUS.md) records current scope, while [Interfaces](docs/INTERFACES.md) records privacy/schema boundaries and [Recovery](docs/RECOVERY.md) separates generated-data tests from owner data.

Use GitHub **Security > Advisories > Report a vulnerability** in this repository for a private report. See the [private reporting page](https://github.com/Limited-Underground/TrackMyClicks/security/advisories/new). Availability of the private-reporting control was not rechecked by the offline November 3 documentation task. If that control is unavailable, open a public issue requesting a private reporting route without disclosing the vulnerability, personal data or exploit details.

Include the affected version/commit, impact and a minimal synthetic reproduction. Do not send real activity databases, credentials, identifying paths, typed content or private logs. Coordinate disclosure with the maintainer after a fix. No guaranteed response time or automatic disclosure deadline is asserted.

Local-only storage is not encryption or anonymity of the aggregate file. Treat activity totals, backup files, identifying paths and diagnostic UI exports as private. Never attach an owner profile to a public issue or use it as a test fixture. No supported remediation/release schedule is promised during the freeze.
